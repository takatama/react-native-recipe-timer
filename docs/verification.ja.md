確認日: 2026 年 10 月 4 日。今回の検証はローカルの Web アプリを対象とし、原作の Expo アプリは変更していない。

## 自動検証

| 対象 | 結果 | 範囲 |
| --- | --- | --- |
| TypeScript / 配信用ビルド | 合格 | `npm run build` |
| 計画・進行エンジン | 13 件合格 | 依存関係、資源制約、進行状態、期限付きタイマー |
| サーバー | 22 件合格 | 取り込み、入力・取得先の検証、API の応答と異常系 |
| 画面コンポーネント | 5 件合格 | 終了確認、コンロ変更、下書きの取消・採用、ダイアログ中の音声操作禁止 |

上記は計 40 件。`npm test` に全件を含めている。AI 応答のテストは stub を使用し、実 Gemini API は呼び出していない。
画面テストは JSDOM で dialog、音声、fetch をモックしたコンポーネントテスト。終了確認の取消・確定、コンロ変更による再計算・保存・調理中の変更禁止、下書きの保存前未採用・取消・明示保存後の採用、ダイアログ中の音声操作禁止を確認した。

## ブラウザでの実操作

デスクトップの Codex 内ブラウザで確認した。390 px の表示確認は画面幅の確認であり、モバイル実機の検証ではない。

| 操作 | 確認した結果 |
| --- | --- |
| 3 料理の調理を開始 | 一つの進行画面で複数料理を扱える |
| 鮭を焼く待ち時間と、スープの具材を切る手作業を同時に開始 | 2 つの名前付きタイマーが独立して進む |
| 一方のタイマーを停止・延長 | 個別に操作でき、他方の進行を維持する |
| 進行中にページを再読込 | 保存した期限を使って残り時間を復元する |
| 期限を超えた状態で再表示 | 自動完了にせず、確認待ちとして残す |
| テキストを取り込んで編集・保存 | 下書きを確認してからレシピとして採用できる |
| サーバーを停止して再読込 | 一度読み込んだアプリをオフラインで開き、タイマーを操作できる |
| 390 px / 1365 px で表示 | 両幅で表示確認。390 px で横はみ出しなし |

最終の UI 修正では、終了確認をブラウザの native confirm から HTML dialog に変更した。
変更後の確認ダイアログは上記の画面テストで確認した。モックを使う画面テストと、ブラウザでの実操作は異なる検証として記録している。

## 未確認・保証しないこと

- 実 Gemini 呼び出しは 0 件。有料の疎通確認、実画像の認識品質、実レシピでの AI 推定精度は未確認。
- 実機の音声認識・読み上げ、カメラ、通知、消灯防止、権限拒否後の端末固有の挙動は未確認。
- ロック中・ブラウザ終了中の指定時刻の音や通知は保証しない。再読込復帰は背景アラームの代替ではない。
- 原画像はレビュー時の表示にだけ用い、保存するレシピには含めない。写真を利用する AI 呼び出しでは API に送信される。
- PWA のインストールと長期間のキャッシュ更新、端末間同期、本番 HTTPS 配信は今回の実操作範囲に含まれない。
- 公開デプロイは行っていない。ローカルサーバーは `127.0.0.1` 接続を前提とする。

## 本番化前の条件

ロック中の通知を製品として約束する前に、[iOS AlarmKit](https://developer.apple.com/documentation/alarmkit) / [Android のアラーム](https://developer.android.com/develop/background-work/services/alarms)を使う補助アプリを実装する。
実機で権限、低電力状態、再起動、延長・取消、複数タイマーの通知を検証する。今回の Web 実装にはこの補助アプリは含まれない。
AI を本番利用する前には、実レシピ・写真で誤読、時間の推定、材料の欠落を測定し、API の費用上限とデータの取り扱いを確認する。
