# Kitchenflow — 問題から組み直す調理アシスタント

調理中に答えてほしいのは「いま何をする？ 次はいつ？」。Kitchenflow は、複数料理の手順と待ち時間を一つの進行画面にまとめる。

## 原作が解こうとしていた問題

確認できる目的は、レシピを「やること」と「所要時間」に分け、現在の工程と残り時間を示し、工程の切り替わりを知らせること。
これは、繰り返す手順を覚え続け、時間を見張り続ける負担を減らす仕組みと解釈できる。

## 今回の設計

最初の画面から料理を選び、コンロ数に合わせた段取りを確認できる。開始後は大きな次の行動と、進行中の名前付きタイマーを優先して表示する。

| 選択 | 理由とトレードオフ |
| --- | --- |
| 一人の調理者・複数料理・有限のコンロ | 同時に手を動かす工程を重ねず、待ち時間を別の準備に使う。複数人の分担は扱わない |
| 手作業と待ち時間を区別 | 調理を時間切れだけで終わったことにしない。完了は利用者が確認する |
| 依存関係と設備を使う決定的な計画 | AI の回答を待たず段取りを出せる。実際の所要時間は人や設備で変わるため予測値 |
| 独立した期限付きタイマー | 別の工程を進めても加熱の残り時間を保持する。ページ再読込後は保存した期限から再計算する |
| レスポンシブな Web / PWA | PC・タブレット・スマホで同じ操作を提供できる。端末をロックした状態のアラームには制約がある |
| 端末内に手順・進行状況を保存 | アカウントなしで主要機能を使える。端末間同期やバックアップはない |

計画は段取りの目安であり、全料理が必ず同じ時刻に出来上がる保証ではない。手作業が遅れた場合も、すでに始めた待ち時間を勝手に停止しない。
終了したタイマーは確認待ちとして残し、実際の仕上がりを見てから次に進む。

## AI・音声・写真の使いどころ

文章からの取り込みは API キーなしでも使える。URL の内容取得、任意の AI 整理、写真の読み取りで入力負担を減らす。
取り込み結果は下書きとして、工程、時間、手作業／待ち時間、設備、材料、出典を確認・編集してから追加する。
AI が推定する工程や時間を、原典の正確な転記と同一視しない。

任意の AI はサーバー側の Gemini 3.8 Flash（`GEMINI_MODEL` で変更可能）を使う。
このモデル名は [Google のモデル一覧](https://ai.google.dev/gemini-api/docs/models)で確認した。
構造化した出力にも誤りはあり得るため、人が確認する導線を維持する。[Gemini の構造化出力](https://ai.google.dev/gemini-api/docs/structured-output)
AI は利用者が実行した取り込み・質問でだけ呼び出し、調理状況を自動変更しない。質問には現在の料理と工程・進行状況を渡す。
写真はレシピの読み取りに使い、原画像は下書きレビュー時の表示にだけ用いてレシピ保存には含めない。加熱の安全性や完成を画像だけで判定する機能は設けない。

音声は「次は？」「完了」などの短い操作と読み上げを補助する。画面のボタンでも同じ操作を提供する。
[SpeechRecognition は対応ブラウザに制限があり、音声をブラウザ提供者のサーバーへ送る場合がある](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。音声利用は任意とし、完全な端末内処理や常時待受を約束しない。

## モバイルでの信頼性

[Screen Wake Lock](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)で、対応端末の画面表示中に消灯を防ぐ。HTTPS が必要で、低電力状態や画面の非表示で解除され得る。
[通知](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)は許可を得た対応ブラウザでの補助。期限の検出は動作中のページに依存し、画面ロック・ブラウザ終了中の指定時刻の通知は保証しない。
再表示時に正しい残り時間へ戻ることと、背景で確実に音を鳴らすことは別の要件である。

本番で「ロック中も必ず知らせる」を提供する前に、[iOS AlarmKit](https://developer.apple.com/documentation/alarmkit) と [Android のアラーム](https://developer.android.com/develop/background-work/services/alarms)を利用する補助アプリを実装し、権限、低電力、再起動、取消・延長を実機で検証する。これは今後の本番化条件であり、今回の実装には含まれない。

## 実績と検証の境界

型チェックとビルド、および計画・進行エンジン 13 件、サーバー 22 件、画面操作 5 件の計 40 件のテストが合格した。実 API の代わりに stub を使った AI 応答の検証を含む。

| 要件 | 確認したこと |
| --- | --- |
| 一人分の手作業と設備容量に矛盾がない | エンジンのテストと 3 料理の並行開始 |
| 各タイマーが独立して進む | 2 つの同時タイマー、個別停止、延長を実操作 |
| 再読込後に実時間の経過が反映される | 期限からの復帰、期限超過を確認待ちに保持 |
| 取り込み結果を確認して採用する | テキスト取り込みの下書きを編集して保存 |
| 意図せず状態を変更しない | 終了確認の取消・確定、調理中のコンロ変更禁止、下書きの取消、ダイアログ中の音声操作禁止を画面テスト |
| 接続がなくても調理を続けられる | サーバー停止後のオフライン再読込とタイマー操作 |
| 狭い画面でも操作できる | 390 px と 1365 px で表示確認。390 px で横はみ出しなし |

実操作はデスクトップのアプリ内ブラウザで行った。画面操作テストはブラウザ API をモックした JSDOM によるもので、実機の証拠とは分けている。[検証記録](verification.ja.md)に確認内容と未確認範囲をまとめた。
実 Gemini 呼び出しは 0 件。音声、通知、消灯防止、カメラ、ロック中のアラームは実機で未確認であり、自動テストの合格をその代わりにしない。
公開デプロイは行っていない。食卓の時刻からの逆算、複数人の分担、端末間同期、信頼できる背景アラームは次の段階で扱う。
