# Kitchenflow

「いま何をする？ 次はいつ？」に答える、複数料理の調理アシスタント。
原作の Expo アプリはリポジトリのルートに残し、このフォルダーに新しい Web / PWA を実装している。
問題の分析、設計判断、実装範囲は [再設計の説明](../docs/product-redesign.ja.md)を参照。

## 起動

Node.js 22.12 以降を使用する。以下は `web/` で実行する。

```sh
npm install
npm run dev
```

[http://127.0.0.1:4317](http://127.0.0.1:4317) を開く。初期の料理を選び、段取りを確認して開始できる。
サーバーは標準でループバックにだけ接続する。任意の `PORT` でポートを変更できる。

```sh
npm test
npm run build
npm start
```

`dev` は開発用の表示、`build` は型確認と配信用ファイル生成、`start` は生成済み `dist/` の配信。
`test` は計画・進行エンジン、サーバー、画面の操作テストを実行する。確認済みの結果は末尾と [検証記録](../docs/verification.ja.md)を参照。

## 任意の AI 設定

キーなしでも料理の段取り、タイマー、手動編集、テキスト・URL 取り込みを使える。
写真の読み取り、AI での取り込み、文脈を使った質問には Gemini API キーが必要。
`web/.env.example` を `web/.env` にコピーして設定し、サーバーを再起動する。

```dotenv
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.8-flash
PORT=4317
AI_DAILY_REQUEST_LIMIT=50
```

キーはサーバーの環境変数として読み込む。公開用のブラウザ変数や Git 管理に入れない。
モデルは [Google の一覧](https://ai.google.dev/gemini-api/docs/models)を確認して変更できる。
API は利用者が実行した AI 取り込み・質問でだけ呼び出す。キーのない写真・質問は利用できない理由を返す。
AI の実 API は未試験で、有料 API の疎通確認は行っていない。

同時 AI 呼び出しは 1 件、短時間の呼び出し数と一日分の呼び出し数に上限を設ける。
一日上限は UTC 日付・サーバーのメモリー内で管理し、再起動するとリセットされる。金額上限ではないので、提供者側の予算・利用制限も設定する。

## 操作

1. 料理を選び、使えるコンロ数に合わせた段取りを確認する。
2. 調理を開始し、大きく表示された次の行動を実行する。
3. 手作業は終わったら完了を知らせる。待ち時間は独立したタイマーとして進む。
4. 時間が来たら仕上がりを確認する。必要なら延長し、確認してから完了にする。
5. レシピを取り込む場合は、下書きと出典を確認・編集してから追加する。

進行状況とレシピはブラウザの端末内ストレージに保存する。再読込後は期限から残り時間を再計算する。
ストレージ削除や別端末への移動には引き継げない。計画の所要時間は目安であり、加熱の完了・安全性を判定する機能ではない。

## 音声・モバイル・通知

音声操作と読み上げは対応ブラウザで任意に使用する。[音声認識はブラウザによって外部サービスへ音声を送る](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)。オフラインの音声認識や常時待受を保証しない。
写真はカメラで撮影した画像または選択した画像を取り込む。AI を使うと、文章・取得した URL の内容・写真、質問時の調理文脈が Google の API に送られる。
画像の読み取り結果は必ず下書きとして確認し、誤読・抜け・推定した時間を修正する。原画像はレビュー時の表示にだけ用い、レシピ保存には含めない。

[消灯防止](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API)と[通知](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API)にはブラウザの対応と権限が必要。表示中のページを補助する機能として扱う。
画面をロックした場合やブラウザを終了した場合に、指定時刻で音・通知が届く保証はない。期限の復元は、背景アラームの保証とは異なる。

スマホの音声・カメラ・通知・消灯防止を実機で使うには HTTPS の構成が必要。PC の `localhost` は開発用途で例外的に利用できるが、LAN の HTTP アドレスは同じ条件ではない。
このローカルサーバーは同一オリジン・ループバックを前提にし、LAN 公開をサポートしない。HTTPS 配信や外部公開は別途設計・確認する。
PWA としてのインストール可否はブラウザに依存する。公開・本番デプロイはこの実装作業の範囲に含めていない。

## 検証記録

型チェックとビルド、エンジン 13 件 + サーバー 22 件 + 画面操作 5 件 = 40 件のテストが合格。AI 応答は stub、画面操作はブラウザ API をモックした JSDOM による検証であり、実 Gemini 呼び出しは 0 件。
アプリ内ブラウザで 3 料理の並行開始、独立した 2 タイマー、個別停止と延長、再読込復帰、期限超過の確認待ち、取り込み下書きの編集保存を確認した。
サーバー停止後のオフライン再読込とタイマー操作、390 px / 1365 px の表示も確認した。390 px で横はみ出しはなかった。
実機の音声・通知・カメラ・消灯防止・画面ロック中のアラームは未確認。詳しい確認範囲は [検証記録](../docs/verification.ja.md)を参照。
本番で背景アラームを約束するには、[iOS AlarmKit](https://developer.apple.com/documentation/alarmkit) / [Android のアラーム](https://developer.android.com/develop/background-work/services/alarms)を使う補助アプリと実機検証が必要。今回には含まれない。
